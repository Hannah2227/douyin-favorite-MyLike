# MyLike Electron — 产品需求文档（PRD）

> 版本：v1.22 · 更新：2026-10-23 · 状态：0.8.3 Windows 预览版；生产包完整回归通过，真实收藏待验
> 本文是后续开发的统一依据；需求变化直接修改正文，并在文末简要记录。

## 1. 背景与目标

MyLike 已具备喜欢列表采集、筛选与播放能力，但 WPF 宿主、页面脚本和业务状态逐步耦合，影响维护与可靠性。本次参考现有项目的业务和经验，用适合 Electron 的方式重构。

- **收录与整理**：把自己的抖音喜欢、收藏作品和收藏夹元数据保存在本机，支持采集、检索和回看。
- **方便回看**：顺序或随机播放筛选结果，支持视频、图集、实况图集与续播。
- **容易维护**：结构直观、状态明确、核心逻辑可独立验证，便于 AI 辅助开发。

**已确定的边界**：采用 Electron；请求在真实抖音页面上下文中执行，由页面 SDK 处理签名；不走本地逆向签名。旧用户数据、文件格式和登录态不迁移；本期只支持 Windows x64，macOS / Linux 留待以后，当前不考虑移动端。

开发者自主决定架构、界面、流程与代码复用方式。原项目及 DoLike 提供参考，不要求文件、按钮或交互一一对应。

**本期不做**：媒体完整下载与离线播放、发布作品与个人推荐列表采集、本地用户名密码体系、云同步、浏览器扩展、自建评论客户端。收藏首期支持本人收藏作品和收藏夹的只读同步、筛选及播放，不提供远端收藏管理、收藏数据导入导出或收藏的合集 / 音乐 / 短剧专项采集。离线可浏览已收录元数据，播放仍依赖网络与平台可用性。

## 2. 用户与使用场景

| 用户 / 场景 | 期望结果 |
| --- | --- |
| 喜欢内容较多的用户 | 快速找到旧内容，按筛选范围连续或随机回看 |
| 多抖音账号用户 | 切换账号时，列表、登录态和任务归属清楚且隔离 |
| 首次使用 | 打开应用 → 添加账号并登录 → 采集 → 浏览或播放 |
| 日常使用 | 打开已有列表 → 检索 / 筛选 → 播放；需要时增量采集 |
| 采集中断 | 已收录内容保留，处理登录或验证问题后继续未完成部分 |
| 整理与备份 | 批量删除本地条目、取消远端点赞，或导出后在新环境合并导入 |

## 3. 功能需求

以下均为本轮目标能力，里程碑仅划分实现顺序。入口和布局可以合并、重组，验收以目标场景为准。

### 3.1 账号与登录

| ID | 需求 | 行为要求 |
| --- | --- | --- |
| F1.1 | 账号管理 | 添加、重命名、切换、删除账号；左栏直接提供改名与删除入口，账号显示为“本地自定义名(抖音名)”，未核验时标注；无账号可进入引导，已有本地数据无需登录即可浏览 |
| F1.2 | 抖音登录 | 在应用打开的抖音窗口完成登录；登录成功核对实际账号身份，不能只凭 Cookie 存在判断 |
| F1.3 | 会话隔离 | 每个账号使用独立持久会话；身份不匹配时停止旧任务，切换不串数据、不改变应用主题 |
| F1.4 | 退出与删除 | 退出登录保留本地内容；删除账号须确认，将清除该账号的本地列表、收藏夹关系、任务、播放记录、登录态和缓存，同时从应用历史备份中清理该账号，不新建删除前备份；保留其他账号及仍被引用的共享作品；损坏或占用的备份阻止删除成功，已导出的外部文件由用户管理 |

### 3.2 喜欢列表采集

| ID | 需求 | 行为要求 |
| --- | --- | --- |
| F2.1 | 全量采集 | 分页获取平台实际返回的列表，保存标题、作者、发布时间、封面、媒体类型等元数据，去重入库 |
| F2.2 | 增量与续采 | 补充新增内容，同时保留此前未完成的深层断点；不能因为发现已有作品就遗漏未采完部分 |
| F2.3 | 长任务控制 | 支持暂停、继续、停止；长列表按预算分段自动接续，每页数据与断点一起保存；允许已提交页之间回收引擎，重启后可恢复 |
| F2.4 | 验证与错误 | 区分未登录、需验证、限流、网络故障与页面崩溃；崩溃保留断点并暂停，不能标成用户停止；需人工处理时显示窗口，处理成功后继续仍有效的任务 |
| F2.5 | 进度与结果 | 显示新增、累计、阶段和异常原因；预算耗尽、游标停滞或异常空页不能报告为全部完成 |
| F2.6 | 列表更新 | 提交后合并通知、更新列表；保持筛选和滚动，有活动选择时提示新内容，不改变既有操作快照 |

采集完整性以接口实际可返回的内容为限，不承诺与抖音展示的喜欢总数一致；一次未返回某作品不等于用户已取消点赞。

默认操作先继续未完成任务；没有未完成任务时检查新增，遇到整页已收录内容后接续原有深层断点。“从头遍历”可显式重新扫描到平台末尾。暂停、停止与重启均不擅自发出后续请求；网络故障和页面导航中断有限重试，限流或验证问题暂停并保留原因，处理后手动继续。

### 3.3 内容浏览与筛选

| ID | 需求 | 行为要求 |
| --- | --- | --- |
| F3.1 | 内容列表 | 展示封面、标题、作者、日期与类型；喜欢、收藏及按收藏夹浏览均在接近底部时自动追加下一页，不再提供手动加载更多。保留虚拟化和滚动位置，不重复读取已有页；请求防重，筛选 / 账号切换丢弃旧响应，隐藏页面不自动加载；失败保留已加载条目并提供显式重试，已到底不再请求 |
| F3.2 | 检索筛选 | 顶部搜索标题 / 作者，下一行筛选全部 / 视频 / 图集、年 / 月；条件与结果一致，快速切换不显示旧响应 |
| F3.3 | 排序统计 | 按发布时间倒序，移除排序下拉框；显示当前范围条数，数据占用见仪表盘和设置 |
| F3.4 | 批量选择 | 支持单选、清空、选择全部筛选结果；固定选择时的条目范围，超出单次上限明确提示；不能仅选中已渲染的卡片却显示“全部” |
| F3.5 | 仪表盘 | 独立导航入口，显示当前账号喜欢和收藏按作品去重后的本地总数、视频、图集、年份数量、最近收录和续播；移除任务动态与内容来源。第四项为本机元数据占用，包含全部账号的数据库、WAL 与共享内存文件，不含媒体缓存、会话和备份，并说明范围；统计不受内容库筛选影响，账号切换不展示旧账号数据；读取失败可重试，不显示假零值；回看使用当前账号完整内容范围 |

### 3.4 播放与原页

| ID | 需求 | 行为要求 |
| --- | --- | --- |
| F4.1 | 队列 | 点播、顺序播放、洗牌播放、上一条 / 下一条、队列跳转；队列来源是创建时的筛选快照；打开后跨作品保持展开，由用户手动关闭；列表和关闭按钮避开系统窗口按钮，窗口缩放、最大化与全屏下均可操作 |
| F4.2 | 媒体 | 静态图每张 3 秒；实况播完回到该张静态照片 2 秒，再翻页或重播，暂停冻结倒计时；静态资源不可用时以首帧兜底；手动翻图停在当前张，可恢复轮播；媒体等比完整居中，离开释放媒体与声音 |
| F4.3 | 控制 | 关闭连播循环当前作品，开启时播完下一条，图集末张等待音乐；左右翻图、悬停高亮进度、倍速、音量、全屏和快捷键；按钮 / 队列 / 滚轮 / 自然连播换作品均保持全屏，主动退出或返回内容库才退出；滚轮有手势节流 |
| F4.4 | 续播 | 手动退出或关闭应用后记住作品、队列与位置；自然播完不再提示继续；快速切歌时旧取链不能覆盖新播放 |
| F4.5 | 取链失败 | 播放时获取新鲜链接，有限预取与重试；网络、验证、解码失败分别反馈，不随意标记作品已删除 |
| F4.6 | 原页看评论 | 暂停并保存位置，在用户系统默认浏览器打开指定作品；浏览器登录态独立，不共享应用会话；返回应用后手动继续播放，不通过焦点变化或外部标签关闭自动恢复；打开失败保留暂停并明确反馈 |

原页入口只接受校验后的作品 ID，由主进程构造固定的抖音 HTTPS 地址，不接收任意外部 URL；切作品后旧播放请求不能打开错误目标。

### 3.5 数据管理与取消点赞

| ID | 需求 | 行为要求 |
| --- | --- | --- |
| F5.1 | 本地删除 | 单条 / 批量移除目标账号的本地条目，不修改抖音点赞；批量删除前备份，失败整批回滚；再次采到或导入时允许重新收录 |
| F5.2 | 导入导出 | 新的版本化元数据格式，校验、去重并合并到指定账号，支持跨账号汇总；失败或取消不留下半份数据 |
| F5.3 | 取消点赞 | 播放中单条与列表批量取消，显示操作账号、目标数量和结果；成功一条保存一条，可停止未发出的后续操作 |
| F5.4 | 结果不明确 | 写请求发出后超时、断网或退出，记录为结果未知，保留本地条目；不自动当作失败重复发送 |
| F5.5 | 数据保护 | 读取失败不伪装成空列表；保存失败明确反馈；数据库升级和大批量导入前创建一致性备份 |

本地删除与远端取消点赞必须使用不同文案。导入文件不携带认证信息，也不能作为当前账号已点赞的证明；远端操作绑定实际登录账号和目标作品。

取消点赞一次最多 1000 条；开始前确认固定目标和操作账号，先暂停采集。停止时等待当前有界请求结果，后续未发送项可手动继续。历史未知结果阻止同作品重复发送；“重新核验”只读当前点赞状态，仍点赞时须重新选择并确认才可再次操作。

### 3.6 设置与诊断

- 深浅主题、播放偏好和快捷键统一管理；主题切换入口放在左栏账号上方，切换抖音账号不重置外观；窗口按钮区域随主题变化，播放视图使用深色，退出后恢复。
- 下拉框统一主题、选中和禁用样式，支持键盘选择、Esc 取消、点击外部收起；长菜单可滚动，小窗口与缩放下不越界。
- 展示数据位置、版本、缓存清理和脱敏诊断入口；错误给出原因与可执行的下一步。
- 任务详情集中展示进度、失败原因和重试入口，关键结果不能只靠短暂提示。
- 左栏主题入口下依次为常见问题、使用教程、项目地址，样式统一；前两项应用内可离线查看，项目地址交给系统默认浏览器。左下角不再显示版本号。
- 设置按通用、播放、快捷键、账号、数据与存储、关于分组，可检索；提供启动页、界面缩放、窗口位置与尺寸记忆、减少动画、自动播放、滚轮切换、失焦暂停、快进步长和音量 / 倍速设置，均持久保存并实际生效。启动不自动恢复后台任务。
- 可配置快捷键仅保留 12 项：播放 / 暂停（空格）、上一条（↑）、下一条（↓）、快退 / 上一张图（←）、快进 / 下一张图（→）、全屏（F）、静音（N）、连播（A）、取消当前点赞确认（Z）、倍速循环（0.75x–2x，默认不绑）、原页看评论（默认不绑）、播放列表（Q）。PageUp / PageDown 固定切换作品，Esc 优先退出全屏或返回；仅在设置中管理，播放器无快捷键帮助、侧栏展开和复制链接功能。冲突不保存，可恢复默认；旧默认键升级，仍支持的自定义键保留。输入框、菜单和弹窗优先，快捷键不绕过远端操作确认。
- 数据设置提供只读数据库完整性检查和复制脱敏诊断；检查结果不能伪装为成功。关于提供版本及发布页入口，不引入后台自动更新或遥测。

### 3.7 收藏与收藏夹

| ID | 需求 | 行为要求 |
| --- | --- | --- |
| F6.1 | 独立来源 | 独立“收藏的内容”入口，收藏成员关系和喜欢分开；同一作品的元数据复用，账号、来源、收藏夹、任务与游标不串用 |
| F6.2 | 同步与续采 | 在真实页面 SDK 上下文读取全部收藏作品、本人收藏夹及夹内作品；分页和断点事务保存，暂停 / 继续 / 停止，重启不自动恢复；首次和完成后的新一轮均完整扫描，不以整页已收录作品代替收藏夹同步 |
| F6.3 | 分组更新 | 按收藏夹浏览与搜索筛选；完整返回收藏夹列表后更新夹列表，某夹完整返回后再移除旧分类关系；异常空页、重复游标或失败不提前清空旧关系；作品未出现在本轮返回中不自动删除本地元数据 |
| F6.4 | 播放与并行 | 按全部收藏或指定收藏夹创建固定顺序 / 洗牌队列，切换界面不改变已有队列范围；同步时可以播放，取链优先；喜欢采集、收藏同步与取消点赞互斥，账号切换先等待任务收口 |
| F6.5 | 只读边界 | 收藏列表与收藏播放不显示取消点赞入口；仅采集作品元数据与分类，不执行远端取消收藏或修改收藏夹；取链、媒体与续播复用播放器 |

## 4. 页面与关键交互

| 区域 | 内容 |
| --- | --- |
| 仪表盘 | 账号概览与适度品牌装饰、内容统计、开始 / 继续回看、收录作品各发布年份数量及最近收录；年份按当前账号的喜欢与收藏作品去重，缺失日期归未知，不计为 1970；不展示任务动态、来源分布，回看与年份卡片并排，小窗口纵向排列，启动页可设置 |
| 内容库 | 侧栏保留账号和导航，主题切换放在账号上方；顶部搜索及专属自动采集按钮，其他页面不显示该顶栏按钮；放大采集按钮与续播提示，保证文字易读；筛选栏放顺序 / 洗牌播放与年月筛选，下方为内容数量、导出、批量选择和网格；标题最多两行，移除装饰文案及重复状态说明 |
| 收藏库 | 独立搜索与筛选状态；收藏夹下拉、同步 / 暂停 / 继续、分页与分组进度；按当前范围播放，首期不显示批量远端操作 |
| 播放视图 | 左栏进入时收起，无展开入口；窄顶栏保留返回，紧凑底栏分组放置播放、时间 / 队列位置和工具，播放 / 暂停键与前后切换键统一使用透明底；作者 / 日期 / 文案浮在画面下方；队列浮出常驻并避让系统标题栏，全屏恢复贴近顶部；切换作品保留全屏，返回以淡出 / 淡入衔接原页面，保留筛选与滚动，避免侧栏动画挤压画面 |
| 连接与任务 | 顶部紧凑账号连接区，下方直接显示喜欢采集、收藏同步和取消点赞三个任务块；数量、状态、异常及暂停 / 继续 / 停止就地展示。不设统一任务表、搜索、类型 / 状态筛选或独立详情面板；取消点赞记录按需展开，保留最近 50 项历史选择、逐条结果和只读核验，未知结果自动展开。诊断和本次运行记录合入底部折叠区；未知总量不显示假百分比，切换账号或历史记录不串结果 |
| 账号与设置 | 账号管理、登录状态、应用偏好、数据与诊断 |

同一时刻激活一个抖音账号。支持喜欢采集或收藏同步时播放、后台批量取消点赞时进入播放器并连续播放；媒体使用 CDN，页面请求串行调度，取链优先于下一项后台操作，不中断已发出的写请求。喜欢采集、收藏同步与取消点赞互斥；喜欢播放中可发起单条取消，已有取消任务时不重复创建。切账号先收口旧任务，迟到结果不能修改新账号或新队列。

登录、验证、空列表、无筛选结果、加载失败分别展示可操作状态。任务中断后保留结果与断点，用户主动停止的任务不擅自重启。

主界面与播放器共用 React 应用，内容库保留有界 DOM 以平滑返回，全屏容器不随作品重建；离开时立即暂停，过渡结束释放媒体。无双浏览器控件，图片与预取缓存有界；尊重系统减少动画设置。

应用窗口、任务栏、免安装 EXE 与界面品牌统一使用用户提供的粉色爱心圆角图标；项目入口使用 GitHub 标识。装饰不展示虚构统计，任务、数据检查和诊断均使用实际结果。

主界面顶栏空白与标题、左栏品牌和顶部留白可拖动窗口；搜索、菜单、按钮和账号控件保留正常交互，播放器仅窄顶栏空白可拖动，全屏时禁用窗口拖动。

## 6. 技术架构（高层）

**工程选择：Electron + TypeScript + React + SQLite。** 一个桌面工程，主界面与播放器共用本地 UI；业务通过受限 preload / IPC 调用服务，无需独立 HTTP 后端。

```text
React 界面 / 播放器 → 受限 preload / IPC → 账号、采集、播放、数据管理服务
                                           ├─ SQLite / 数据库 worker
                                           └─ 抖音适配器 → 账号 Session / 页面 SDK
```

- 浏览器适配器执行单次页面请求；翻页、节奏、断点、完成判定与重试属于应用服务。
- 抖音引擎独立于本地 UI，优先采用隐藏 BrowserWindow，按需启动、空闲后释放，登录和验证按需可见；作品原页交给系统默认浏览器，不再创建内置评论窗口；SDK 在隐藏状态下的表现须先实测。
- SQLite 管理账号、作品、账号成员关系、任务与断点、播放快照及设置；内容和来源关系分开，账号作用域明确。
- 收藏使用独立成员、收藏夹、夹内关系和同步任务表；已有 Electron 数据库升级到 v6 前保留一致性备份。账号删除时同步清理所有受支持版本的应用备份，失败不能报告为已全部删除。
- 元数据与断点事务提交；媒体链接只作短期缓存。数据库、会话、日志和备份分别组织，不访问旧版用户目录。
- 构建与打包优先评估 electron-vite、electron-builder；具体版本、驱动与命令在能力验证时确定，PRD 不展开接口和表结构。

## 8. 风险与维护规则
