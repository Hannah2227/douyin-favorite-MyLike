# 当前分支评估与改进路线

评估日期：2026-10-10。本地起点为 `627eede`（批量取消点赞：筛选条件 + 失败重试），origin 为 `lfu45757-star/douyin-favorite-MyLike`，upstream 为 `Hannah2227/douyin-favorite-MyLike`。

本次对比依据是本地源码及上游 main 的 README，并非完整的跨分支代码差异审计。上游文档已列出多账号、续播、主题及更多播放器能力；不能把这些直接视为当前分支已有的能力。

## 本次实现

1. **列表排序**：发布时间升降序、作者、标题；顺序播放保留前端队列顺序，不再由宿主重新按时间排序。洗牌仍保留随机行为。
2. **精确的选择性批量范围**：用预览 ID 快照约束主列表，替换原先将多个作者拼成搜索词、将日期近似成单一年月的实现；范围有可见说明及清除入口。
3. **日期与勾选一致性**：按本机日历解析日期，以次日零点前一秒作为结束，支持跨月和夏令时；空作者匹配零条；筛选变化后移除隐藏勾选，并同步年月控件状态。

范围快照只保存于内存，刷新后仍约束原批次，不会自动把后来采集的作品加入取消范围。排序也只在当前窗口生命周期保留。

## 后续优先级

| 优先级 | 方向 | 依据与建议 |
| --- | --- | --- |
| P1 | 失败重试与中断恢复 | `FailedIds()` 当前按历史失败记录取 ID，没有合并 `PendingIds`；中断后尚未尝试的作品可能不在重试集合。应按作品归并最新结果，并单独提供「继续未完成任务」，展示将执行的数量。 |
| P1 | 存储错误恢复 | 批量服务首次写日志在 try/finally 之外，finally 中写日志又早于结束通知；磁盘满或目录不可写可能影响状态恢复。应保证 UI 解锁、保留可恢复快照，并提供明确错误提示。 |
| P1 | 自动化回归 | 已补列表操作的 JavaScript 回归测试。下一步为目标解析、失败日志归并、断点恢复增加不依赖 WebView2 的测试，再接入 CI 构建。 |
| P2 | 同步上游成熟功能 | 优先评估多账号隔离、续播及主题的相关提交；逐项迁移并验证本分支批量取消功能。账号切换时需同时隔离任务、日志及播放队列。 |
| P2 | 大列表体验 | 当前每批追加 60 张卡片，但持续滚动仍会积累 DOM；可改为虚拟列表，并缓存搜索索引。先用 1 万 / 5 万条样本测量响应时间与内存。 |
| P2 | 本地整理能力 | 增加本地标签、自定义播放列表、按筛选导出；标签独立于抖音点赞状态，备份格式需要版本号及兼容迁移。 |
| P3 | 宿主维护与发布 | 从 MainWindow 拆出队列构建和命令处理；逐步用可还原的依赖替代手工复制 SDK DLL，并验证 WebView2Loader 的发布产物。 |

## 验证方式

- `dotnet build DouyinShuffle.slnx --no-restore`（首次构建需先还原依赖）。
- `node --test tests/library.test.cjs`：覆盖排序、精确作者范围、日期边界及主界面事件联动；测试使用模拟 DOM，不访问抖音。
- 手动验收：在列表切换四种排序；点击卡片确认顺序播放；用多个作者或跨月日期进入选择性取消；改变分类或搜索，确认已隐藏作品不再保持勾选。

自动化测试不代替真实 WebView2 的视觉、播放与账号操作验收。
